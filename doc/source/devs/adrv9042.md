# ADRV9042

The ADRV9042 models validate JESD204B/C transport settings and solve the external
DEVCLK, SYSREF, clock generator, and FPGA clocks. Supply DEVCLK and each link's
interface sample rate from an **ACE-approved configuration**. Passing transport
validation or solving a clock tree does not approve a complete firmware profile.
Internal PLLs, RF LOs, DFE filters, carrier routing, and TDD link sharing are not
synthesized. The model does not import ACE files or program hardware.

## Standalone links

`adijif.adrv9042_rx`, `adijif.adrv9042_tx`, and `adijif.adrv9042_obs` model one
framer or deframer. Their `link_index` selects the hardware instance; observation
RX defaults to framer 2. Set `reference_clock` in Hz before solving. This is the
physical DEVCLK input, distinct from the existing JESD-derived `device_clock`.

```python
import adijif

system = adijif.system("adrv9042_rx", "ad9528", "xilinx", 122_880_000)
system.fpga.setup_by_dev_kit_name("zcu102")
rx = system.converter
rx.reference_clock = 245_760_000
rx.set_quick_configuration_mode("M16L8Np16S1", "jesd204c")
rx.sample_clock = 491_520_000
config = system.solve()
```

Mode IDs describe transport tuples, **not ADI use-case IDs**. Presets choose
zero control bits, full sample resolution, and canonical valid framing. `N`,
`CS`, `HD`, `K`, and `E` can be adjusted after selecting a preset. JESD204B
requires `20 <= F*K <= 256`, divisible by four, and `K <= 32`. JESD204C requires
`F*K = 256*E` and `K <= 256`; `multiframe_clock` then represents LEMC.

`converter_clock` reports the interface sample rate for compatibility with
generic tools; it does not describe the analog ADC/DAC sampling clock. The model
checks a positive interface rate up to 491.52 MSPS and a 312.5 Mb/s transport
floor. The lane-rate ceilings are 12.5 Gb/s for JESD204B and 32.44032 Gb/s for
JESD204C. Complete rate/profile compatibility remains ACE's responsibility.

## Combined operation

`adijif.adrv9042` exposes `framer0`, `framer1`, `framer2`, `deframer0`, and
`deframer1`. The aliases `adc`, `obs`, and `dac` refer to framer 0, framer 2,
and deframer 0. Initially only framer 0 and deframer 0 are enabled.

```python
system = adijif.system("adrv9042", "ad9528", "xilinx", 122_880_000)
system.fpga.setup_by_dev_kit_name("zcu102")
device = system.converter
device.reference_clock = 245_760_000
device.obs.enabled = True
device.obs.lane_mapping = [4, 5]
config = system.solve()
```

`lane_mapping` lists physical lanes in logical lane order and defaults to an
identity mapping. Active links must use disjoint physical lanes within each
direction. Opposite directions may reuse lane numbers. Hardware logical-lane
capacities are 8/4/2 for framers and 8/4 for deframers. Active framers must have
power-of-two sample-rate and lane-rate ratios. `cddc_cduc_bypassed=True` additionally
limits `M` to 32. Routing observation data to a chosen framer remains part of the
ACE configuration; the `obs` alias does not program a data crossbar.

The device requests one shared DEVCLK and equal-frequency SYSREF outputs for
each active link. SYSREF candidates are exact common submultiples of DEVCLK
and all active LMFC/LEMCs. `sysref_dividers` defaults to 1–64 and may be changed.
Disabled links contribute no FPGA, JESD, or clock requirements. Editing profile
settings and calling `solve()` again rebuilds the constraints; reapply any custom
clock constraints when changing the configuration.

Only CPLEX is supported. Infeasible external clock or FPGA constraints produce
a solver failure. Software checks do not establish physical link operation,
clock phase noise, or SYSREF setup/hold margins.

Explorer's JESD Mode Selector supports hardware-instance selection and `E`
filtering. System Configurator exposes standalone links and the combined device,
including all five enable controls, lane maps, and explicit DEVCLK entry. CLI/MCP
uses the same registered names and supports nested `converter_properties`.

See `examples/adrv9042_example.py` for standalone and RX/ORx/TX clock solves.
